## Where the numbers come from
Every value in the text, tables and plots is generated by `../paper_eval/` (see its README). Table rows are read from
`tables/`. The TikZ figures were drawn from the pipeline's own output for benchmark S2.
`paper_eval/check_paper_numbers.py` recomputes all 69 numbers quoted in the prose and in the hand-drawn figures and
finds each exact phrase in the source. It passes 69/69.
The Brotli/Zstandard comparison (`compare_gp.py`) ran on a second machine (Python 3.10, AArch64). There, every
pipeline size matched the first machine byte for byte.

The screenshot (Fig. 6) shows the real web front end (`web/`) and the unmodified `api/server.py`. FastAPI could not be
installed in Claude's workspace, so the server code ran behind a minimal stand-in HTTP layer for the screenshot.
You can retake it with `python3 main.py --web --port 8000` if you prefer.

## Differences from the earlier `main.tex` / README claims (measured, not edited)
| Earlier claim | Measured |
|---|---|
| "Canonical Huffman" gives 37–73% compression | The Huffman stage makes every benchmark 2.0–2.7× *larger* than the bytecode. It only helps once the bytecode exceeds about 5.7 KB. |
| "up to 75.0%" via columnar Huffman | 75.0% (S4) is real, but entropy coding was skipped on all 7 benchmarks. The columnar container is also larger than plain CLIR on every benchmark. |
| GVN drives S3's reduction | GVN removes 0 instructions on all 7 benchmarks. Folding removes S3's redundancy first. |
| 52 or 54 tests | 39 core tests (all pass) + 16 UI tests (not run here). |
| "100% lossless round-trip" | True for Huffman. CLIR needs a register→literal table that is not serialized. The columnar format loses 7 of 14 loop-carried φ arguments. |
| "74.5% average bytecode reduction" | 68.7–87.8% per benchmark against the raw TAC text. |

## Bug found (not fixed in your code)
`core/optimizer.py::_eval_binary` folds `/` and `%` with Python floor semantics (`//`, `%`). C truncates toward zero,
so `-31 % 1000` folds to 969 instead of −31. This changed the output of 214 of 1,000 random programs.
A truncating version, `paper_eval/variants.py::CDivOptimizer`, fixes all 1,000. Fixing it in `core/` takes about two lines.
